# Deployment Guide

Practical production deployment of Lumina RAG on a single VPS or small cluster. Pairs with [SETUP_GUIDE.md](../SETUP_GUIDE.md) (which covers local development).

---

## Server requirements

| Resource | Minimum | Recommended |
|----------|---------|-------------|
| CPU | 2 vCPU | 4+ vCPU |
| RAM | 2 GB | 4–8 GB (more if running Ollama locally) |
| Disk | 20 GB SSD | 50 GB+ SSD (uploaded documents + Postgres data) |
| OS | Linux (Ubuntu 22.04+, Debian 12+) | same |
| PHP | 8.3+ with extensions: `pdo_pgsql`, `mbstring`, `xml`, `zip`, `intl`, `bcmath`, `redis` (optional), `gd` or `imagick` (PDF parsing) | same |
| PostgreSQL | 16 with pgvector 0.6+ extension | same — co-located or managed (RDS / Supabase / Neon) |
| Redis | 7+ (recommended for cache + session + queue) | same |
| Web server | Nginx (preferred) or Apache + mod_php / FPM | Nginx + PHP-FPM |
| Process manager | Supervisor for queue workers | systemd units also fine |
| TLS | Let's Encrypt or managed cert | required for production |

**Sizing notes**:
- Embedding generation is CPU-light if you're using OpenAI (network-bound). If you're running **Ollama locally**, plan for 8 GB+ RAM and a GPU for tolerable latency.
- pgvector IVFFlat memory is roughly proportional to (chunks × dimensions × 4 bytes). 1 M chunks × 1 536 dims ≈ 6 GB index — plan database RAM accordingly.

## Environment configuration

Production `.env` differs from the dev template. Key differences:

```env
APP_ENV=production
APP_DEBUG=false
APP_URL=https://your-domain.com
APP_KEY=base64:…                 # generated by php artisan key:generate

# Logging
LOG_CHANNEL=stack
LOG_STACK=daily,stderr           # or syslog/papertrail
LOG_LEVEL=warning                # debug → info in production

# Database
DB_CONNECTION=pgsql
DB_HOST=<host or socket>
DB_PORT=5432
DB_DATABASE=lumina_rag
DB_USERNAME=lumina
DB_PASSWORD=<strong>

# Redis-backed everything
SESSION_DRIVER=redis
SESSION_LIFETIME=120
CACHE_STORE=redis
QUEUE_CONNECTION=redis
REDIS_HOST=127.0.0.1
REDIS_PASSWORD=<strong>
REDIS_PORT=6379

# RAG
OPENAI_API_KEY=sk-…
RAG_EMBEDDING_PROVIDER=openai
RAG_EMBEDDING_MODEL=text-embedding-3-small
RAG_LLM_PROVIDER=openai
RAG_LLM_MODEL=gpt-4o
RAG_LOG_CHANNEL=rag
RAG_LOG_LEVEL=info

# File storage
FILESYSTEM_DISK=local            # or s3 — see "Object storage" below
```

> **Never commit `.env`.** Set values via your platform's secret store (systemd `EnvironmentFile=`, Kubernetes secrets, AWS Parameter Store, etc.).

## Initial deployment steps

```bash
# 1. Pull code + install
git clone <repo-url> /var/www/lumina && cd /var/www/lumina
composer install --no-dev --optimize-autoloader
npm install --ignore-scripts
npm run build

# 2. Provision .env with production values, then:
php artisan key:generate --force
php artisan migrate --force
php artisan db:seed --force      # optional: initial settings + AI model registry rows

# 3. Cache framework state for performance
php artisan config:cache
php artisan route:cache
php artisan view:cache
php artisan event:cache

# 4. Permissions for writable dirs
chown -R www-data:www-data storage bootstrap/cache
chmod -R 775 storage bootstrap/cache
```

Re-run `composer install --no-dev --optimize-autoloader && php artisan migrate --force && npm run build && php artisan optimize` on each release. Always run `php artisan optimize:clear` first if you previously cached config and changed `.env`.

## Web server

### Nginx + PHP-FPM (recommended)

`/etc/nginx/sites-available/lumina`:

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name your-domain.com;

    root /var/www/lumina/public;
    index index.php;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    # Increase to fit max upload (50 MB + headroom)
    client_max_body_size 64M;

    # Long-lived connections for SSE chat streaming
    proxy_read_timeout 3600s;
    fastcgi_read_timeout 3600s;
    fastcgi_buffering off;             # required for SSE — flush events as they arrive

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    # Vite-built assets
    location ~* \.(?:css|js|woff2?|svg|png|jpg|webp|ico)$ {
        expires 1y;
        access_log off;
        add_header Cache-Control "public, immutable";
        try_files $uri =404;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    }

    location ~ /\.(?!well-known).* { deny all; }
}
```

Key things people miss:
- **`fastcgi_buffering off;`** is required for `/api/chat` SSE streaming. Otherwise nginx buffers the entire response and the client sees it all at once.
- **`client_max_body_size 64M;`** must exceed the 50 MB upload cap (PHP's `upload_max_filesize` and `post_max_size` need to match — check `php.ini`).
- The Vite-built bundle has content-hashed filenames (`assets/app-AbC123.js`), so the year-long immutable cache is safe.

```bash
sudo ln -s /etc/nginx/sites-available/lumina /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### PHP-FPM tuning

`/etc/php/8.3/fpm/pool.d/lumina.conf` — start with:

```ini
[lumina]
user = www-data
group = www-data
listen = /run/php/php8.3-fpm.sock
listen.owner = www-data
listen.group = www-data

pm = dynamic
pm.max_children = 20            ; tune to (RAM / per-process MB)
pm.start_servers = 4
pm.min_spare_servers = 2
pm.max_spare_servers = 6
pm.max_requests = 500           ; recycle workers to fight memory creep

php_admin_value[memory_limit] = 256M
php_admin_value[upload_max_filesize] = 60M
php_admin_value[post_max_size] = 60M
php_admin_value[max_execution_time] = 120
php_admin_value[opcache.enable] = 1
php_admin_value[opcache.memory_consumption] = 128
php_admin_value[opcache.max_accelerated_files] = 10000
```

OPcache should be **on** in production. Restart PHP-FPM after each release.

## Queue workers (critical)

Document processing happens in `ProcessDocumentJob`. **No worker = uploads stuck on `pending` forever.**

### Supervisor config

`/etc/supervisor/conf.d/lumina-worker.conf`:

```ini
[program:lumina-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/lumina/artisan queue:work redis --sleep=3 --tries=3 --max-time=3600
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=2                     ; scale up if you have many concurrent uploads
redirect_stderr=true
stdout_logfile=/var/log/supervisor/lumina-worker.log
stopwaitsecs=3600              ; let in-flight jobs finish before SIGTERM
```

```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start lumina-worker:*
```

After each deploy:

```bash
php artisan queue:restart        # gracefully restarts all workers after they finish current jobs
```

### systemd alternative

If you don't want Supervisor, a systemd unit per worker works equivalently. Use `Restart=always` and `RestartSec=10`.

### Failed jobs

```bash
php artisan queue:failed                    # list
php artisan queue:retry all                 # retry everything
php artisan queue:retry <id>                # retry one
php artisan queue:flush                     # delete all failed jobs
```

The `failed_jobs` table grows unbounded — schedule `queue:prune-failed` weekly via the scheduler.

### Scheduler

`crontab -e`:

```
* * * * * cd /var/www/lumina && php artisan schedule:run >> /dev/null 2>&1
```

## Object storage (uploaded documents)

The default `FILESYSTEM_DISK=local` puts files in `storage/app/`. For production:

- **Single-server**: `local` works, but **back up `storage/app/`** alongside the database. Document files are not stored anywhere else — losing them means losing the source content (the chunks + embeddings would still exist as residue).
- **Multi-server / autoscale**: switch to S3 (or compatible: MinIO, R2, B2). Set:

```env
FILESYSTEM_DISK=s3
AWS_ACCESS_KEY_ID=…
AWS_SECRET_ACCESS_KEY=…
AWS_DEFAULT_REGION=us-east-1
AWS_BUCKET=lumina-documents
AWS_USE_PATH_STYLE_ENDPOINT=false
```

The DocumentService uses `Storage::` so no code changes are needed — the disk swap is transparent.

## Using Ollama in production

Ollama can replace OpenAI for embeddings, the LLM, or both — useful for data-residency / offline / cost-control reasons.

### Same machine

```bash
# Install Ollama (see https://ollama.com/download)
ollama pull nomic-embed-text         # 768-dim embeddings
ollama pull llama3.1:8b              # or 70b if you have the GPU

# Run Ollama as a systemd service (default install does this)
systemctl status ollama
```

Then create `ai_models` registry rows pointing to `http://localhost:11434`. **Do not** expose Ollama publicly — it has no auth.

### Dedicated GPU server

Run Ollama on a separate node and point `base_url` at it from your app server. Use a private network or a TLS-terminated reverse proxy with auth.

### Performance expectations (rough)

| Model | Hardware | Tokens/sec |
|-------|----------|-----------|
| `llama3.1:8b` | CPU only (16 cores) | 5–15 |
| `llama3.1:8b` | RTX 4090 | 80–120 |
| `llama3.1:70b` | A100 80GB | 25–40 |
| `nomic-embed-text` | CPU | 100–300 chunks/min batched |

For interactive chat, anything below ~30 tok/s feels slow. Use streaming (already enabled) so users see tokens as they generate.

## Database backups

PostgreSQL — `pg_dump` daily, ship to off-host storage:

```bash
pg_dump -Fc -d lumina_rag -f /backups/lumina-$(date +%Y%m%d).dump
aws s3 cp /backups/lumina-$(date +%Y%m%d).dump s3://lumina-backups/
find /backups -name 'lumina-*.dump' -mtime +14 -delete
```

Vector data in `ve_{dim}` tables is large — `pg_dump` with `-Fc` (custom format) compresses well. For multi-TB datasets, consider WAL archiving + base backups (pgBackRest, Barman).

**Test restore** quarterly. A backup you've never restored is hypothetical.

## Observability

### Application logs

Configured via `RAG_LOG_CHANNEL` and `RAG_LOG_LEVEL` env vars. In production, ship logs to a central aggregator:

- **stderr → docker → log driver** if containerized.
- **Filebeat / Vector / Fluentbit** tailing `storage/logs/*.log`.
- **Papertrail / Logtail / Datadog** via the `LOG_STACK=stderr,papertrail` channel composition.

### Metrics worth alerting on

| Metric | Source | Alert threshold |
|--------|--------|-----------------|
| Document `failed` count (last 1h) | `documents` table | > 5 in an hour |
| Queue depth (pending jobs) | `jobs` table count | > 100 sustained |
| Embedding API error rate | application logs | > 5% over 15 min |
| pgvector search p95 latency | application logs | > 2s |
| LLM completion latency | application logs | > 30s |
| Disk usage on `storage/` | OS | > 80% |
| Postgres connection pool exhaustion | pg_stat_activity | utilization > 80% |

### Health endpoint

`GET /api/health` returns 200 when the app is reachable. Wire this into your load balancer's health checks. For deeper checks (DB, Redis, queue), consider extending the endpoint or adding a separate `/api/health/deep`.

## Security checklist

- [ ] `APP_DEBUG=false` in production. Verify by visiting an unknown route — should be a generic 404, not a stack trace.
- [ ] HTTPS enforced (HTTP → HTTPS redirect in nginx).
- [ ] `APP_KEY` set and **stable** across deploys (rotating it invalidates all sessions).
- [ ] Database, Redis, Ollama bound to localhost or a private network — **never** to `0.0.0.0` on a public IP without auth + TLS.
- [ ] Storage volume backups verified by restoring at least once.
- [ ] OpenAI API key scoped to a single project, with usage limits set on the OpenAI dashboard.
- [ ] Rate limiting on `/api/chat` (currently the only throttle is `5/60` on `/api/auth/login` — consider extending to chat to control AI spend).
- [ ] CORS — Laravel's default `config/cors.php` allows the same origin only; if you serve the SPA from a different domain, add it explicitly.
- [ ] Sanitize Trix-edited `description` fields server-side before storage. The frontend renders these with `v-html` — see L6 in the UI audit notes.
- [ ] Log retention policy — purge rotated logs older than 30–90 days to limit blast radius if logs leak.

## Deploy hooks (zero-downtime-ish)

A simple bash deploy script that minimizes downtime:

```bash
#!/usr/bin/env bash
set -euo pipefail

cd /var/www/lumina

git fetch --all
git reset --hard origin/main

php artisan down --refresh=15        # show maintenance page; auto-retry every 15s

composer install --no-dev --optimize-autoloader
npm install --ignore-scripts
npm run build

php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache
php artisan event:cache
php artisan queue:restart            # workers exit gracefully and supervisor respawns them

php artisan up
```

For true zero downtime, deploy with [Deployer](https://deployer.org) or a blue/green pattern (atomic symlink swap of `current/` → `releases/{ts}/`).
